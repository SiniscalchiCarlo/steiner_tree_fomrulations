Analysis of the Steiner Formulation Benchmarks

Short answer: you have enough information to answer the exercise well for the three formulations that were actually implemented and benchmarked, namely undirected cut, undirected flow, and directed cut. You do not yet have enough to fully answer the exercise exactly as written, because it asks for four formulations and the current solver registry contains only three.

Main caveat. The current repository does not implement a fourth formulation in the benchmark registry. Also, the 120-second run used the default Gurobi cut settings for undirected cut and undirected flow, while directed cut was run with Cuts = 0 when --cuts was not provided. This means the comparison is informative, but not perfectly symmetric.

Main dataset used below: run 20260406_113835, 100 instances, 1 thread, 120-second limit.

Answer

Based on the available results, the practical ranking of the formulations is clear. The directed cut formulation is the strongest by a wide margin. It solves all 100 benchmark instances within 120 seconds, while undirected flow solves 39 and undirected cut solves 22. This ranking is consistent across the main metrics requested by the exercise.

1. Overall solution time

The overall runtime comparison strongly favors directed cut. Its median runtime is about 4 seconds, while the medians for the other two formulations are around the full 120-second time limit. Pairwise, directed cut is faster than undirected cut on every instance and faster than undirected flow on 92 out of 100 instances. Undirected flow is the second-best formulation, but mainly on the easier instances.

2. Quality of LP at root node

The root-node LP relaxation is best for directed cut, with the smallest median root LP gap. Then comes undirected flow, and finally undirected cut. This is exactly the pattern one would expect if the directed cut formulation gives a tighter relaxation. A tighter root bound is consistent with the better solve times and the smaller branch-and-bound trees observed for directed cut.

3. Number of branch-and-bound nodes

Again, directed cut is clearly better. Its median branch-and-bound node count is only 48, compared with 770 for undirected flow and 1816.5 for undirected cut. This suggests that the stronger root relaxation of directed cut translates into a much smaller search tree.

4. Time spent for separation problems

Separation is relevant only for the cut formulations. The directed cut model spends far less time in separation than undirected cut, both in absolute terms and in practical impact on the solve. This is important because it shows that the better performance of directed cut is not achieved by paying an excessive callback price. The flow formulation does not use separation, so its separation time is zero.

5. Dependence on the instance

The outcomes depend strongly on instance size and structure. Runtime for directed cut has a strong positive correlation with the number of edges, density, and average degree. The number of terminals matters too, but less for runtime than edge count. For undirected flow and undirected cut, terminal-related measures appear more influential than for directed cut, especially for runtime and separation effort. In short, denser and larger instances are harder for all formulations, but directed cut degrades much more gracefully.

Conclusion. With the data currently available, the strongest answer is that directed cut is the best formulation among the three implemented ones: it has the lowest solution times, the strongest LP relaxation at the root node, the smallest branch-and-bound trees, and moderate separation overhead. The practical results are consistent with the theoretical expectation that stronger formulations should lead to better bounds and faster solves.

  • If the missing formulation is directed flow, it should be implemented and benchmarked before claiming a complete answer.
  • The comparison should ideally be rerun with the same Gurobi cut settings for every formulation, for example --cuts 0 for all of them.

Unexpected-result caveat

The note in the exercise about turning off Gurobi cuts is relevant here. In the current code, the directed cut model explicitly sets Cuts = 0 when no --cuts value is provided, but the other two models keep Gurobi's default cut behavior unless --cuts is set manually. Therefore, if you observe surprising differences, some of them may come from solver settings rather than formulation strength alone. A clean methodological follow-up would be to rerun all formulations with --cuts 0.

Why the 120-second run matters

The earlier 30-second run was enough to identify the best formulation, but not enough to separate hard-from-impossible instances. The 120-second run shows that all 23 formerly unsolved instances are in fact solvable by directed cut, while the other two formulations improve only slightly. That makes the dominance of directed cut much more convincing.
