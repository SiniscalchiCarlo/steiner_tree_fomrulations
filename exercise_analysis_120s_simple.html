Assignment Answer: Comparison of Steiner Formulations

Important note. The exercise asks to compare four formulations, but in the current code and benchmark results only three formulations are implemented and tested: undirected cut, undirected flow, and directed cut. Therefore, the analysis below is complete only for these three formulations.

I used the benchmark run with 100 instances, 1 thread, and a time limit of 120 seconds. The main quantitative summary is:

Formulation Optimal runs Time-limit runs Median runtime (s) Median root LP gap Median B&B nodes Median separation time (s)
directed cut 100 0 4.05 0.0938 48.0 0.725
undirected flow 39 61 120.10 0.1472 770.0 0
undirected cut 22 78 120.02 0.2335 1816.5 18.47

1. Overall Solution Time

The best formulation in terms of solution time is directed cut. It solved all 100 instances, with median runtime equal to about 4.05 seconds. The other two formulations were much slower: both have median runtime around the full 120-second limit, because many instances were not solved within the time limit.

The pairwise comparison confirms this result. Directed cut is faster than undirected cut on 100 out of 100 instances and faster than undirected flow on 92 out of 100 instances. Therefore, directed cut is clearly the fastest formulation overall.

2. Quality of LP at Root Node

The quality of the LP relaxation at the root node can be evaluated through the root LP gap: smaller gap means stronger relaxation. The best formulation is again directed cut, with median root LP gap equal to 0.0938. The second-best is undirected flow with 0.1472, while undirected cut is the weakest with 0.2335.

So the computational results are consistent with the idea that a stronger formulation gives a tighter root bound and better overall performance.

3. Number of Branch-and-Bound Nodes

The branch-and-bound tree is much smaller for directed cut. Its median number of nodes is only 48, compared with 770 for undirected flow and 1816.5 for undirected cut.

This means that directed cut allows Gurobi to prune the search tree much more effectively. This is also coherent with the stronger LP relaxation observed at the root node.

4. Time Spent for Separation Problems

Separation is used only in the cut formulations. The directed cut formulation spends much less time in separation than undirected cut: median separation time is about 0.725 seconds for directed cut and 18.47 seconds for undirected cut.

Therefore, the callback and separation procedure do not appear to be a bottleneck for directed cut, while they are much more expensive for undirected cut. For undirected flow the separation time is zero because no separation callback is used.

5. Dependence on the Instance

The results depend strongly on instance characteristics. In particular, runtime increases when the number of edges, density, and average degree increase. For directed cut, the correlation between runtime and number of edges is about 0.864, which is strong and positive.

The number of terminals also matters, especially for undirected flow and undirected cut. For example, for undirected flow the correlation between runtime and number of terminals is about 0.646, while for undirected cut it is about 0.482. This suggests that larger and denser instances are harder for all formulations, but directed cut still remains the most robust one.

Conclusion

Among the three available formulations, directed cut is clearly the best. It is the fastest, it has the best LP relaxation at the root node, it explores the smallest branch-and-bound tree, and it spends a moderate amount of time in separation. Undirected flow is generally better than undirected cut, but both are much weaker than directed cut on this benchmark set.

More

There are some additional points that are useful to mention.

  • The 120-second run is much more informative than the 30-second run. At 30 seconds, directed cut solved 77 instances; at 120 seconds it solved all 100. This shows that the previously unsolved instances were hard, but not impossible for directed cut.
  • I checked the objective values on all jointly solved instances, and there were no mismatches between formulations. This is a strong empirical indication that the implementations are correct and model the same problem.
  • The comparison is not perfectly symmetric, because in the current code directed cut uses Cuts = 0 by default, while the other two formulations keep Gurobi's default cuts unless the parameter --cuts is set explicitly.
  • For a cleaner final comparison, it would be better to rerun all formulations with the same Gurobi cut setting, for example --cuts 0.
